# PR 05 — Static GLB/glTF Asset Importing

**Status:** Development branch candidate for v0.2.0. Browser GPU testing still required.

## What this adds

- `GLTFLoader`: loads binary `.glb` or JSON `.gltf` glTF 2.0 assets through `fetch`.
- `parseGLB`: validates GLB v2 headers, JSON chunk, BIN chunk, lengths and alignment.
- `decodeAccessor`: decodes little-endian glTF accessors, including interleaved buffer views, `Uint8`/`Uint16`/`Uint32` triangle indices and normalized vertex attributes.
- A native scene hierarchy with node matrices, quaternion/TRS transforms, mesh instances and multiple mesh primitives.
- PBR metallic/roughness values, base-color and packed metallic/roughness PNG/JPEG textures, with sRGB/linear separation.
- Missing vertex normals generated for triangle primitives.
- External buffers/images, bufferView-embedded images, and base64 or percent-encoded data URIs.
- A fully original generic GLB model at `assets/models/starfire-relay.glb` for the interactive demo.

## Example

```js
import { Engine, GLTFLoader } from './src/index.js';

const engine = await Engine.create({ canvas: document.querySelector('canvas') });
const result = await new GLTFLoader().load('/assets/models/starfire-relay.glb');

for (const root of result.roots) engine.scene.add(root);
console.log('Imported nodes:', result.nodes.size, 'warnings:', result.warnings);
engine.start();

// On unload: remove the scene's imported roots, let the renderer sweep GPU
// resources (or dispose the renderer), then dispose the decoded image bitmaps.
// result.roots.forEach(root => engine.scene.remove(root));
// result.dispose();
```

Direct parsing works too:

```js
const bytes = await (await fetch('/assets/models/starfire-relay.glb')).arrayBuffer();
const result = await new GLTFLoader().parse(bytes);
```

For JSON glTF with relative external resources, supply a base URL:

```js
const doc = await (await fetch('/assets/models/example.gltf')).json();
const result = await new GLTFLoader().parse(doc, {
  baseURL: new URL('/assets/models/example.gltf', location.href).href
});
```

Option `sceneIndex` overrides `document.scene`. `result.scene` is an engine `Scene` already containing the imported roots, and can be assigned directly to `engine.scene`; alternatively, add `result.roots` to your existing scene.

## Supported subset

- glTF 2.0, `TRIANGLES` primitive mode, one default or selected scene.
- `POSITION` float32; `NORMAL` and `TEXCOORD_0` read via accessors. Normalized integer vertex channels and interleaved data supported. Normal vectors generated if absent.
- Triangles with `UNSIGNED_BYTE`, `UNSIGNED_SHORT`, `UNSIGNED_INT` indices, or unindexed triangles.
- Nested nodes with `matrix` or TRS and quaternion rotation; mesh sharing between node instances.
- `pbrMetallicRoughness` materials, optional textures and factors, and emissive factor.
- glTF samplers for wrap and nearest/linear filtering; mipmap filter requests approximate nearest/linear at the base level and create a warning.
- Core PNG/JPEG images embedded in GLB buffers, in data URIs, or fetched using a relative URI.

## Deliberate limitations

This is **not a fully conformant glTF 2.0 loader**. The importer *explicitly rejects* features that the v0.2.0 renderer cannot reproduce correctly:

- Skinning, morph targets, animation, sparse accessors, and compressed geometry/extensions such as Draco.
- `KHR_*` required extensions, texture transform extensions, `TEXCOORD_1` material selection.
- Material alpha masking/blending, double-sided geometry, normal/occlusion/emissive texture maps, and advanced PBR material extensions.
- Non-triangle primitive modes (lines, points, strips, fans), and `COLOR_0` vertex color materials.
- Different sampler modes for base color and packed metallic/roughness maps on the same material.

Other attributes such as `TANGENT` do not affect rendering. Mipmap generation, image-based reflections, and advanced shading remain future work. Large/untrusted files are bounded and checked for invalid offsets. The loader does not execute scripts from model data.

### Compatibility note

Files exported from Blender with **Apply Modifiers**, glTF 2.0, **no animations**, `Opaque` materials, and standard metallic/roughness textures are the intended first-test targets. Some Blender exports will use features outside this subset; loader errors identify the unsupported feature rather than silently dropping it.

## Testing

```powershell
npm run ci
npm run dev
```

Open `http://localhost:5173/?renderer=webgpu` and `http://localhost:5173/?renderer=webgl2`.

Verify that the Starfire Relay model is visible, textures appear on its top panel, no console errors occur, changing camera angles retains correct hierarchy, and the FPS/draw call counters update. Compare behavior on the Radeon RX 6600 and test at least one exported Blender GLB model using the supported subset.

Automated tests cover GLB structure, strided and normalized accessor decoding, uint32 indices, missing normals, multi-primitive meshes, nested matrices, external fetch paths, malformed files, unsupported features, bitmap cleanup, and local HTTP serving. They do **not** substitute for real WebGPU/WebGL 2 shader tests on hardware.

The included Starfire Relay GLB and textures were created for the public engine demonstration and contain no RideOps content.
