# Starfire Engine — v0.2.0 PR 01: Core Stability and Security

Status: Implementation candidate. This is **not** the v0.2.0 release.

## Implemented

- Correct WGSL vertex normal transformation without relying on an unsupported `inverse()` built-in. The cofactor approach supports nonsingular nonuniform and mirrored transforms.
- Create the WebGPU depth attachment even when the canvas already matches the desired viewport dimensions.
- Release partially initialized GPU resources before falling back to WebGL 2 if WebGPU initialization fails.
- Replace the development server's unrestricted project-root file serving with an allowlisted static server. Only the index and designated asset folders may be served; dotfiles, private folders, traversal attempts, and symlink escapes are denied.
- Preserve the constructor-provided orbit camera settings when resetting controls.
- Add regression tests for these behaviors.

## Verification performed

- `npm run ci`: 19/19 tests passing on Node.js 22.
- Local HTTP smoke test: `/` and `/src/index.js` return 200; `/.env`, `/.gitignore`, and `/tests/scene.test.js` return 403.
- GPU/browser rendering remains unverified in this environment. Test WebGPU and WebGL 2 on actual browsers and hardware before merging.

## Manual graphics validation

1. `npm run dev`
2. Open `http://localhost:5173/?renderer=webgpu` in Edge or Chrome with a supported GPU.
3. Verify that the 3D demonstration renders and camera orbit/zoom work.
4. Switch to `?renderer=webgl2`; verify parity at this basic stage.
5. Resize the browser; reload both backends; check the developer console for errors.
6. Inspect `chrome://gpu` or `edge://gpu` if WebGPU remains unavailable.
