# PR 07: Visibility, Instancing, CPU Profiling and Diagnostics

Baseline: `development` commit `1d3c2529a18d15973d67d68ba06e6cfa6d92faf5` (PR 06 scene hotfix). Change is part of the 0.2.0 development train, not an independent version-number bump.

## Functionality

### Conservative frustum culling

`Visibility.js` computes local bounding spheres from existing geometry attributes or legacy vertices. For `Geometry` instances the bounds are cached by `version` (call `markDirty()` after edits). The spheres are transformed with a matrix-norm upper bound so shear, rotations and non-uniform scales remain conservative. Six frustum planes are extracted from a column-major clip matrix; near-plane handling differs for WebGPU and WebGL 2.

The main camera and directional shadow pass are **culled independently**. A mesh offscreen but inside the shadow frustum may still cast a shadow. The engine avoids disposing of merely offscreen geometry. Culling is enabled on built-in perspective cameras and can be toggled in the demo.

Custom camera implementations can opt in via `camera.frustumCulling = true`. Explicit `InstancedMesh` batches are currently retained conservatively as whole groups until per-instance bounding tests are added.

### Indexed GPU instancing

`InstancedMesh` holds matrices as a finite `Float32Array` containing 16 floats per instance, in column-major order. Use `setInstances()` to update data and increment the resource version. One instanced main draw and, when enabled/visible, one instanced shadow draw are submitted per mesh entity. Internal shaders provide a regular and instanced variant, using four additional `vec4` vertex attributes and a 64-byte matrix step rate.

```js
import { Entity, InstancedMesh, Mat4, createBox } from './src/index.js';
const matrices = new Float32Array([
  ...Mat4.compose([0, 0, 0]),
  ...Mat4.compose([3, 0, 0]),
  ...Mat4.compose([6, 0, 0])
]);
const group = new Entity('Batch');
group.add('mesh', new InstancedMesh(createBox(), { color: [0.2, 0.7, 1, 1] }, matrices));
scene.add(group);
```

It is an **explicit** batching API; arbitrary entities with similar materials are not automatically merged. Each instance uses the same material and mesh, with its transform relative to the parent entity. Up to 16,384 instances per mesh. Large instances count toward rendered triangles, not individual draw calls. Per-instance colors, animation/skinning, and per-instance culling remain future improvements.

### CPU timing and memory estimates

`FrameProfiler` tracks exponentially smoothed CPU update, render-submission, and total CPU work times. `gpuMs` is deliberately **null**. CPU render submission is not GPU execution time, and FPS alone cannot reveal if the GPU, CPU, browser frame pacing or a tab policy is limiting rendering.

Renderer diagnostics include resident geometry count, texture count, instance-buffer count and **estimated** GPU bytes. Estimates cover known uploaded buffers, texture pixel surfaces and shadow/depth maps; they **exclude** browser/driver padding, pipeline/shader allocations, MSAA and other internal overhead. They must not be presented as authoritative VRAM usage.

## Hardware and benchmark validation

Run `npm run ci`; run `npm run dev`; visit both `?renderer=webgpu` and `?renderer=webgl2` on the AMD RX 6600, then compare:

- idle scene, shadows on vs off;
- culling on vs off while looking away from the objects;
- 256 instances on vs off;
- exposure and environment intensity held constant;
- repeat the five-second benchmark after warmup and with animations paused;
- check console for WGSL/GLSL errors and device/context-loss issues;
- reload, rotate camera, resize, and ensure object counts/geometry caches do not grow uncontrollably.

The pre-PR07 screenshot read 32 FPS on both backends with 79 main and 79 shadow draws. This is a baseline observation, **not** evidence of a particular bottleneck or a performance guarantee. Do not claim success against a 60 FPS target without measured hardware results.

## Known limitations

- GPU shader variants are not fully validated until run on real browsers/hardware (the current CI uses Node mocks).
- GPU timestamp queries, pipeline statistics, GPU occlusion culling, automatic opaque material batching and per-instance frustum culling are not part of PR 07.
- The renderer still supports a maximum of 2,048 submitted mesh entities per frame. One instanced mesh can represent many individual objects.
- Shadow mapping is a single fixed directional orthographic volume, not cascaded shadows.
