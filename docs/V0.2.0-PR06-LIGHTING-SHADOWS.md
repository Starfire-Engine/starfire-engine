# PR 06 — Directional shadows and procedural environment preview

## Scope

This milestone adds a single opt-in **directional-light shadow map** using a fixed-size orthographic light volume, plus an **approximate** sky/horizon/ground reflection term in the PBR material path.

- WebGPU: `depth24plus` shadow texture, depth-only pass, depth-comparison sampler, 3×3 PCF with `textureSampleCompareLevel`.
- WebGL 2: 24-bit depth framebuffer texture, depth-only program, comparison sampling with `sampler2DShadow`, 3×3 PCF.
- Both backends share the same shadow settings and world-space projection, with correct differences in normalized depth and framebuffer vertical orientation.
- Legacy materials receive direct-light shadows without changing their base-color API. PBR materials add a procedural environment diffuse/specular approximation. The environment model is **not a physical convolution of an HDR cubemap**.

## API

```js
import { Lighting, ShadowSettings, EnvironmentLighting } from './src/index.js';

scene.lighting = new Lighting({
  direction: [0.65, 0.95, 0.42],
  shadows: new ShadowSettings({
    enabled: true, mapSize: 1024, radius: 14, center: [0, 0, 0],
    near: 0.5, far: 100, distance: 40, bias: 0.0025, strength: 0.88
  }),
  environment: new EnvironmentLighting({
    skyColor: [0.23, 0.39, 0.68],
    horizonColor: [0.58, 0.64, 0.77],
    groundColor: [0.055, 0.075, 0.11],
    intensity: 0.8
  })
});
```

Set `scene.lighting.shadows.enabled = false` to skip the shadow pass; default scenes have shadows disabled and environment intensity zero for compatibility.

## Implementation notes

1. The shadow projection is generated with backend-specific clip-space depth (`0..1` WebGPU, `-1..1` WebGL 2), with a stable up vector near vertical light directions.
2. Only geometry currently in the render queue casts shadows. There is no separate caster/receiver layer mask yet.
3. 3×3 PCF smooths hard edges but does not implement PCSS contact-hardening or an ambient-occlusion solution.
4. The `bias` is a normalized shadow-depth offset (not meters). Depth bias also applies during shadow rasterization to mitigate acne. Fine detail depends on resolution and world-space radius.
5. Shadow map GPU resources are reallocated only if the map resolution changes; the previous texture/framebuffer is released.
6. The PBR environment term is a directional gradient approximation. It does not sample an HDR cube map, prefilter specular MIP levels, or use a BRDF integration LUT.
7. `renderer.drawCalls` remains the main color pass draw count; `renderer.shadowDrawCalls` separately reports shadow pass draw calls.

## QA

```bash
npm run ci
npm run dev
```

Run both `?renderer=webgpu` and `?renderer=webgl2` on supported hardware. Verify: soft shadows on foundation/plinths, the original GLB still imports, color/metallic materials remain correct, toggling shadows removes them immediately, changing environment intensity affects reflective materials, window resize works, and there are no shader compilation errors or browser GPU validation warnings.

**Automated tests/mock passes are not a substitute for checking real hardware.**

## Not in scope

HDR/cube-map IBL, reflection probes, cascaded shadow maps, spot/point light shadows, MSAA resolution, normal maps, physically correct area lighting, double-sided materials, alpha-tested shadows, animation, volumetric lighting, tone-map calibration.

No RideOps code or assets are included.
