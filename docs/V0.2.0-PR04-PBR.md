# Starfire Engine v0.2.0 — PR 04: Metallic-Roughness PBR (Development)

## Base revision

Implemented against `development` at `c28f7809e663eed96f45b3118726183018310d3e` (after PR 03). This is an overlay patch for that commit, not a separate working engine release.

## Implemented

- New `PBRMaterial` class with `metallic`, `roughness`, `color` (RGBA factor, **linear**), `baseColorTexture` (sRGB), `metallicRoughnessTexture` (**linear**, green=roughness, blue=metallic), `emissive` (linear RGB), and existing `TextureSampler` support.
- New scene-level `Lighting` class: configurable directional light direction, linear RGB color, scalar intensity, constant ambient color/intensity, and exposure.
- WGSL and GLSL ES 3 shader implementations of Cook–Torrance direct-light specular reflection: GGX NDF, Schlick-GGX geometry term, Schlick Fresnel, energy-aware diffuse attenuation.
- One lighting/material data interface on WebGPU and WebGL 2; buffers, uniforms, and 2 texture bindings are updated consistently.
- Color workflow for **PBR**: sRGB texture sampling to linear RGB, linear lighting and emissive addition, ACES-fitted tone mapping, then linear-to-sRGB transfer before display.
- Reusable 1x1 metallic-roughness fallback map, cached texture binding groups and renderer-owned cleanup; updates to texture version trigger a new upload and appropriate bind group.
- PBR gallery added to `demo/main.js`: dielectric, polished metal, brushed metal, rough metal, and a packed metallic-roughness map example, with an exposure slider.
- Legacy `Material` and plain `{ color: [...] }` stay on their original diffuse/specular branch (not silently converted to PBR).

## Quick start

From the repository root with PR 01–03 already present:

```bash
npm run ci
npm run dev
```

Open `http://localhost:5173/?renderer=webgpu` to verify the WebGPU path, then `http://localhost:5173/?renderer=webgl2` for fallback. Select AUTO to verify normal backend selection.

## Library usage

```js
import { Scene, Lighting, Entity, Mesh, PBRMaterial, createSphere, TextureManager } from './src/index.js';

const scene = new Scene('PBR example');
scene.lighting = new Lighting({
  direction: [0.65, 0.95, 0.42],
  color: [1, 0.96, 0.9], intensity: 3.5,
  ambientColor: [0.8, 0.9, 1], ambientIntensity: 0.2,
  exposure: 1.0
});
const textures = new TextureManager();
const base = await textures.load('/assets/textures/starfire-grid.png'); // sRGB
const packedMR = await textures.load('/assets/textures/metallic-roughness-preview.png', { colorSpace: 'linear' });
const model = new Entity('PBR sphere').add('mesh', new Mesh(createSphere(), new PBRMaterial({
  color: [1, 1, 1, 1],
  baseColorTexture: base, metallicRoughnessTexture: packedMR,
  metallic: 1, roughness: 1, emissive: [0, 0, 0]
})));
scene.add(model);
```

Metallic and roughness factors multiply the texture channels. Roughness is clamped internally to 0.045 to avoid numerical instability in the GGX distribution. The base-color RGB factor is in linear space, and a metal's base color determines its F0 specular hue. Texture colors are decoded by the GPU sRGB texture format.

## Limitations — intentionally NOT included in PR 04

- **No image-based lighting (IBL), reflection probes, HDR environment cubemaps, or real-world reflection sources**. The ambient term is a constant non-physical preview fill (including a modest metal-specular component). Polished metals will look less realistic until IBL is added.
- Single directional key light, not an arbitrary light registry. No cast shadows, reflection maps, normal maps, occlusion maps, or multiscattering compensation yet.
- Opaque materials only: alpha blending, alpha cutoff/masking, double-sided surfaces, and transmission are not implemented.
- BaseColor RGBA factors are multiplied by the sampled texture and alpha is emitted, but the renderer does **not** enable alpha blending or masking.
- This is a first-pass BRDF with no formal color-management calibration, golden-image baselines, or hardware GPU coverage beyond manual browser testing. Tone mapping uses the popular ACES-fitted approximation, not the complete ACES reference workflow.
- Mutable `Material` / `Lighting` objects are validated at renderer submission where relevant; users should not mutate arrays to invalid values.
- Preserving the legacy shader path is deliberate; old materials do not automatically gain PBR.
