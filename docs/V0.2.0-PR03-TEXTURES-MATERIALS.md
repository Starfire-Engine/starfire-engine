# Starfire Engine v0.2.0 — PR 03: Textures and Material Framework

**Scope:** Unreleased `development` work. **Base commit:** `f5617a70e958e3cbbdd1a85509956edfc7cdb864` (PR 02). General-purpose engine code only.

## Implemented

- `Texture2D`: immutable-dimension CPU texture source with either RGBA8 bytes (`fromRGBA`) or an image source (`fromImage`). A browser-only `load(url)` fetches and decodes PNG, JPEG, or other `createImageBitmap`-supported images. Source bytes are copied on construction; `markDirty()` invalidates the GPU version after deliberate edits.
- `TextureManager`: deduplicates in-flight and completed URL fetches, separately for `srgb` vs `linear`; failed requests are evicted for retry. Its cache is CPU-side only. `forget()` and `clear()` remove URL references but do not implicitly dispose still-used renderer resources.
- `Material`: `color` RGBA tint, optional `baseColorTexture`, immutable `TextureSampler`; old `{ color: [...] }` mesh materials still work unchanged.
- `TextureSampler`: wrap (repeat, mirror-repeat, clamp-to-edge), minification/magnification (linear, nearest). No mipmaps or anisotropic filtering yet.
- Two custom shader implementations now pass `TEXCOORD_0` and sample the material base color. A 1×1 white fallback texture preserves untextured materials. Existing directional diffuse/specular lighting remains **non-PBR**.
- WebGPU: one GPU texture and view per texture/version, fragment sampler bind groups per sampler state, sRGB or linear formats, aligned RGBA upload, external image upload.
- WebGL 2: matching sRGB/linear texture formats (`SRGB8_ALPHA8`/`RGBA8`), separate WebGLSampler objects, image and RGBA uploads.
- GPU texture uploads are shared across visible meshes using the same `Texture2D` instance, and disposed when no longer referenced by visible meshes (on subsequent render) or when the renderer is disposed. Dirty textures replace GPU uploads on the next frame. Both backends keep a white default texture until renderer disposal.
- New original `assets/textures/starfire-grid.png` fixture and textured sphere/plane demonstration.

## Public usage

```js
import {
  Texture2D, TextureManager, TextureSampler, Material,
  createSphere, Mesh, Entity
} from './src/index.js';

const textures = new TextureManager();
const grid = await textures.load('/assets/textures/starfire-grid.png');
const material = new Material({
  color: [1, 1, 1, 1],
  baseColorTexture: grid,
  sampler: new TextureSampler({
    wrapU: 'repeat', wrapV: 'repeat',
    minFilter: 'linear', magFilter: 'linear'
  })
});
const sphere = new Entity('Textured sphere')
  .add('mesh', new Mesh(createSphere(), material));
scene.add(sphere);
```

Or directly from raw pixel data:

```js
const white = Texture2D.fromRGBA(1, 1, new Uint8Array([255, 255, 255, 255]));
const normalData = Texture2D.fromRGBA(1, 1, new Uint8Array([128, 128, 255, 255]),
  { colorSpace: 'linear' });
```

## Contracts and limitations

- **Texture color space:** Base-color PNG/JPEG textures default to sRGB and are sampled in linear space via GPU formats. Non-color data maps should use `colorSpace: 'linear'`. No PBR normal/metallic/roughness maps are implemented in PR 03.
- **UV convention:** UV (0,0) refers to the first (top-left) source image pixel. Backend parity must be checked on hardware before merge. Geometry without `TEXCOORD_0` samples `(0,0)`.
- **Sampling:** Bilinear/nearest within one mip level only. Minification over distance will alias until a later mipmap implementation.
- **Transparency:** Alpha is sampled and multiplied but **alpha blending is not enabled**. Transparent materials should not be considered supported yet.
- **Color pipeline:** The output remains a basic legacy lit shader. Proper tone mapping, physically based shading, IBL and shadow passes are scheduled for later PRs.
- **Image lifecycle:** An image-backed `Texture2D` retains its source image. Users managing temporary `ImageBitmap` instances must coordinate `close()` with all users of that image; don't close an image until no renderer will need to re-upload it. `TextureManager.clear()` does not close images.
- **GPU resources:** Cache eviction occurs on the next `render()` call, not instantly upon removing a mesh. A `Texture2D` is reusable across two renderers, which hold separate device-local GPU uploads.
- **Surface restrictions:** One 2D base color texture per material, RGBA8 sources, no compressed formats, atlases, texture arrays, cube maps, mipmap chains, multi-texturing, glTF import, streaming, filtering beyond nearest/linear, or automatic alpha sorting.
- **Public repository:** No RideOps-specific implementation or content.

## Test coverage

Automated coverage includes: constructor validation; CPU copy and dirty versioning; URL fetch/decode success and failure; URL cache deduplication and retry; material backward compatibility; sampler validation; texture resource cache identity and replacement; WebGPU row-aligned RGBA8 upload and external image copy; WebGL 2 formats, samplers and image overload; and mocked per-draw texture bindings/eviction for both rendering backends.

This is not shader compilation on actual AMD/NVIDIA/Intel hardware. GitHub CI runs Node tests, not GPU/browser validation.

## Manual acceptance on RX 6600

1. `npm run ci` must pass and `npm run dev` must serve the demo.
2. Open `http://localhost:5173/?renderer=webgpu`; verify the sphere and top plinth display the blue patterned texture. Pan/orbit; check the Browser DevTools Console for WGSL/validation errors.
3. Open `http://localhost:5173/?renderer=webgl2`; verify orientation, brightness, and wrapping are visually comparable. Check that the gold/blue checker isn't vertically inverted on one backend.
4. Resize the window; ensure neither backend loses its depth buffer or texture bindings.
5. Hide/remove the textured sphere and plane in the demo, re-render, and check for GPU errors; restore meshes and verify upload recovery.
6. Review `git diff` before merging. Keep `main` and `v0.1.0-alpha.1` unchanged until release validation.
