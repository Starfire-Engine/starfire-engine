# Starfire Engine v0.2.0 — PR 02: Rendering and Geometry Foundation

**Status:** Implementation patch for `development`, not a published release.
**Base:** `development` at `7eee3bde4d3a8e761c13bae35508f0d837bd7395`.
**Scope:** General-purpose engine code only. No RideOps assets, systems, source, configuration or documentation.

## Implemented

1. Attribute geometry with validated `POSITION`, optional `NORMAL` and `TEXCOORD_0`, and additional preserved named attributes. Static triangles only; other primitive topologies are not yet supported.
2. `Uint16Array` and `Uint32Array` indices across both renderers, with 32-byte interleaved vertex upload (position3, normal3, uv2). Legacy position/normal interleaved meshes still render, with default UV `(0,0)`.
3. New UV sphere and Y-up plane primitives using the attribute system.
4. Parent-child entity hierarchy with cycle prevention, scene membership protection, ancestor visibility and world-transform composition.
5. Quaternion transform support (`xyzw`) alongside existing Euler rotations; quaternion takes precedence when not null.
6. Shared collection of renderable meshes and model matrices consumed by both backends.
7. `GeometryResourceCache` for shared GPU buffer reuse, version-based refresh, and cleanup of inactive geometry. GPU memory cleanup occurs at the next completed render or `dispose()`, not instantaneously upon removal from a scene.
8. Additional tests and a demo satellite sphere demonstrating hierarchy.

## Example: triangle with UV coordinates

```js
import { Geometry, Mesh, Entity } from './src/index.js';
const triangle = new Geometry({
  attributes: {
    POSITION: new Float32Array([0, 0, 0, 1, 0, 0, 0, 1, 0]),
    NORMAL: new Float32Array([0, 0, 1, 0, 0, 1, 0, 0, 1]),
    TEXCOORD_0: new Float32Array([0, 0, 1, 0, 0, 1])
  },
  indices: new Uint16Array([0, 1, 2])
});
const entity = new Entity('Triangle').add('mesh', new Mesh(triangle));
```

## Example: hierarchy

```js
const parent = new Entity('Parent');
const child = new Entity('Child').add('mesh', new Mesh(createSphere()));
child.transform.position = [2, 0, 0];
parent.addChild(child);
scene.add(parent); // registers both objects
```

## API and compatibility

- `Geometry.getAttribute(name)` retrieves `{array, itemSize}`; supported aliases: `position`, `normal`, `uv`.
- The existing `createBox()` is deliberately unchanged and still returns `{ vertices, indices }` for v0.1.x compatibility.
- Additional geometry attributes are stored but not yet delivered to shaders. PBR/texturing arrives in later work.
- `Geometry.markDirty()` must be called when an attribute buffer is edited. The renderer will replace GPU buffers on the next render.
- Dynamic vertex-buffer streaming, instancing, bounds/culling, mesh streaming and high-level memory budgets are deferred.
- `Scene.remove(child)` detaches that child and subtree from the scene; `parent.removeChild(child)` only unparents a child and leaves it in the scene as a root.
- World-space transform composition is calculated on demand. Large-scene transform caching is deferred.
- Mat4 quaternion composition normalizes quaternion inputs; zero quaternion is rejected.

## Acceptance tests

Run `npm run ci`, then `npm run dev`. Check **both** renderer backends in a hardware browser:

- `http://localhost:5173/?renderer=webgpu`
- `http://localhost:5173/?renderer=webgl2`

Verify that the original demo scene works, a gold sphere orbits the central objects, camera controls behave as before, and no shader/runtime errors appear in the console. Check size/resize behavior. On larger scenes, confirm that disappearing mesh resources are actually freed and redrawn correctly upon reappearance.

Unit tests exercise hierarchy, inherited visibility, 32-bit indices, vertex buffer layout, geometry uploads through mocked WebGPU/WebGL calls, and resource cache cleanup. Browser/GPU rendering has **not** been validated by these tests; manual hardware testing remains mandatory before merging.
